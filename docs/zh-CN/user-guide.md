# 使用手册 —— 从零到每天两分钟

> 这一页写给中文用户，**不是英文页的翻译**。英语那边看的是「结构」，中文这边要的是「动作」，
> 所以例子、说法、重点都按这边的情况写。英文版：[`docs/user-guide.md`](../user-guide.md)。
> 想先看一整天长什么样 → [`walkthrough.md`](walkthrough.md)。装不上 → [`run-with-any-model.md`](run-with-any-model.md)。

---

## 这是什么

吃练记把你的 AI 变成一套**写进你自己文件里**的身体管理流程。

没有 App。没有账号。没有订阅。你的记录就是一个文件夹。

换一句话说：它**不是**一个软件，是**一份文件格式 + 一份说明书**，两样都是纯 Markdown。所以任何一个像样的模型都能读它 —— 包括你下个月才会开始用的那一个。

---

## 5 分钟上手

**1. 拿到这个文件夹**

```bash
git clone https://github.com/adwilds/bodymd
cd bodymd
```

**2. 建你自己的文件**

```bash
cp templates/profile.md profile.md
mkdir -p log reports photos
```

**3. 填四个数**

打开 `profile.md`。一开始只有这四个有用：

```yaml
weight_kg: 75.0
protein_target_g: 145
deficit_target_kcal: 600
program: [deadlift, squat, bench]
```

不知道的一律填 `unknown`。**`unknown` 是合法值，猜不是。**

**4. 把 AI 打开在这个文件夹**

Claude Code、Cursor、Codex，或者任何能读目录的助手，打开的就是这个仓库目录 —— 不是上一级。

**5. 开始**

> 读 SKILL.md，我今天开始记。

## 每天的四个动作

### 动作一 —— 记一顿饭

**吃之前**拍一张，**吃之后**再拍一张。

一起丢给 AI。你要拿回来的是：

- 每一项、分量、热量、蛋白
- 一个**置信度**，以及为什么
- **按什么顺序吃** —— 先吃蛋白

**算错的地方你自己改。** AI 干 80%，你补最后那 20%。你改的那一下会被记进文件，这套东西就是靠这个知道自己哪里不准。

⏱ 目标：15 秒以内。

写出来的一行大概长这样：

```markdown
## Meals
- 21:12 | dinner | 辣椒炒肉 + 米饭 (2 碗) | 720 kcal | P32 C68 F36 | photo: photos/2026-10-12/2112.jpg | source: photo | edited: 米饭按 2 碗计（AI 估 1.5 碗）
- 21:30 | snack | 酸奶 1 杯 | 130 kcal | P6 C15 F5 | photo: photos/2026-10-12/2130.jpg | source: photo | edited: none
```

「我改过」这件事写在**同一行的 `edited:` 字段里**，不是新加一行。这一行改完就永久留在文件里了。

### 动作二 —— 记一组训练

录一组视频，丢过去。

拿回来的只有两样：**动作名和次数**。就这些。

**视频里读不出重量。** 得你开口说：*「硬拉，六十公斤。」* 两秒的事。

然后它会给你下一次的重量。

### 动作三 —— 看今天的缺口

```
消耗 − 摄入 ≤ 600 kcal   →   你在减脂区间里
```

消耗来自你的手表（Oura、Apple Watch、Whoop、Garmin），或者一个估算值。

**这套系统里每个数字都是估算，没有一个是被测量出来的。**

### 动作四 —— 读日报

一屏。缺口、蛋白、睡眠、训练，再加**一句**关于「今天变了什么」。

要滚动，就是太长了。让 AI 砍掉。

## 每周日 —— 周复盘

**这一步最重要。**

说一句：*「周复盘。」*

你拿回三个聚合，加一个改动建议：

| 聚合 | 它在回答什么 |
|---|---|
| 平均缺口 | 计划和你实际过的日子对不对得上 |
| 7 天体重趋势 | 唯一的地面真相 |
| 蛋白达标天数 | 摄入这一侧到底有没有被执行 |

**只需要记住一条规则：**

> 执行率不够的时候，它**不会**给你改热量。它会先让你把执行做起来。

计划没被执行就先去改计划 —— 这是教练行业和产品设计里最常见的同一个错误。

系统**不会**在你没确认的情况下写 `profile.md`。

## 你的数据在哪

```
profile.md          你的基线和目标
log/YYYY-MM-DD.md   一天一个文件，只追加
reports/            生成的报告
photos/             你拍的餐食和训练照片
```

就这些。用任何编辑器都能打开。2050 年还是能读。

**备份随你** —— iCloud、网盘、私有仓库、U 盘都行。你的数据，你决定。

⚠️ **永远不要把 `log/` 或 `profile.md` 提交到公开仓库。** `.gitignore` 已经替你挡了，但别去动它。

## 换模型

这套流程不在乎你用什么模型。

- 今天：Claude
- 明天：GPT
- 下周：Gemini、Kimi、智谱、豆包，或者下一个刚发布的

把新工具指向**同一个文件夹**，说一句 *「读 SKILL.md」*，它就从上一个模型停下的地方接着走。

**这就是整个项目存在的意义。** 别家都让你做数据迁移，这里没有东西可迁。

这条在中文圈尤其成立：**每隔几周换一个模型是日常，不是偏好。** 而你的 200 顿饭不该跟着换。

## 常见问题

**一定要有手表吗？** 不用。没有就用每周体重趋势，慢一点，但不算错。

**一定要付费的 AI 吗？** 不用。能上传文件、能复制的免费额度就够。

**能用它增重吗？** 能。把 `deficit_target_kcal` 填成 0 或者负数，算术会跟着走。

**为什么不做成一个 App？** 因为 App 会把你的数据放回别人的数据库里 —— 那正是这个项目要躲开的东西。见 [`../why-local-data.md`](../why-local-data.md)。

**这是医疗产品吗？** 不是。它不做任何诊断、治疗或治愈。所有数字都是估算。更多见 [`../faq.md`](../faq.md)。

## 出问题了怎么办

| 症状 | 去哪 |
|---|---|
| AI 不听话 —— 自己发明格式、反复问你已经说过的信息、开始给你讲养生 | [`troubleshooting.md`](troubleshooting.md) 第一节 |
| 脚本过不了 —— 校验器报 `FATAL` 或 `WARN` | 同一篇的[第八节](troubleshooting.md#8-校验器报-fatal-或-warn)，V1-V9 每个错误码都对着一个修法 |
| 怀疑某一行写错了 | `python3 scripts/validate_log.py log/` |
| 想确认整个仓库是好的 | `python3 scripts/selftest.py`（20 项，零依赖） |

AI 不读 `SKILL.md`，绝大多数时候只有一个原因：**工具打开在了上一级目录。** 打开在仓库目录里，再让它读一次。
