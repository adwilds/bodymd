# 吃练记（bodymd）· 用任何模型跑起来

**吃练记不是 Claude 的产品，不是 Codex 的产品，也不是 Kimi 的产品。** 它就是一套
Markdown 文件。任何能读文本的模型都能跑 —— 这就是整个项目的全部设计前提。

---

## 一、为什么这件事能成立

`SKILL.md` 是**纯 Markdown + 两行 YAML 头**。没有平台专属语法、没有厂商的函数调用格式、
没有 SDK。所以工具只有三种吃法：

| 工具怎么读文件 | 你要做什么 | 工具 |
|---|---|---|
| **自动读**约定文件名 | 什么都不用做 —— 适配文件已经放在仓库里了 | Claude Code、Codex CLI、Cursor、Copilot |
| **你粘贴**进对话 | 复制 `SKILL.md` + `profile.md` + 当天记录 | ChatGPT、Gemini、Kimi、豆包、通义、DeepSeek 网页版 |
| **你上传**成文件 / 知识库 | 上传一次，之后每次引用 | Kimi、豆包、通义、Gemini |

**减脂中途换模型，你唯一的成本是重新粘一次。数据一次都不用搬。**
这就是「换模型不换数据」这句话的全部含义 —— 而它两分钟就能验证。

---

## 二、⭐ 为什么中国用户比任何人都需要这个

因为你**大概率没得选**：这周用豆包，下周公司让你用通义，DeepSeek 出新版本你想试，
写代码时又切回 Claude。**每换一次工具，你在旧工具里记的东西就废一次。**

- 在英美：换模型是**差异化**（大多数人只用一个 AI）
- 在中国：换模型是**每日现实**，所以「数据在你自己的文件里」是**刚需**，不是卖点

**这也是吃练记有中文版的原因。**

## 三、各工具怎么用

### 1. Claude Code / Claude Desktop

仓库已经是正确形状：`SKILL.md` 带 `name:` 和 `description:` 头。

```bash
git clone https://github.com/<你>/bodymd
cd bodymd
cp templates/profile.md profile.md     # 然后改里面的数字
```

把文件夹放进 skills 目录，或者直接在仓库里开会话，说：

> 读 SKILL.md。开始今天的记录。

### 2. Codex CLI / Cursor / Copilot

**不用解释任何东西。** `AGENTS.md`、`.cursor/rules/bodymd.mdc`、
`.github/copilot-instructions.md` 三个文件已经把工具指向 `SKILL.md`，并且重复了那几条
不能破的规则（只能追加、必须有 `source:`、`unknown` 好过瞎猜）。

打开仓库，正常说话就行：

> 记录这一餐。12:30，食堂，米饭、鱼、青菜。

### 3. Kimi / 豆包 / 通义 / DeepSeek（网页版）

**方式 A：上传（推荐，一次搞定）**

1. 在工具里建一个知识库，或直接上传文件 —— Kimi 和豆包都支持。上传 `SKILL.md` 和
   `profile.md`。
2. 每次开新对话先引用它，然后只粘「今天变了什么」：当天的记录。

**方式 B：纯粘贴（没有任何上传功能也能用）**

开局先把这段发过去：

> 你正在运行「吃练记」工作流（bodymd）。下面是操作手册、我的档案和今天的记录。
> 严格按手册执行。
> **不要编造数字** —— 不知道就写 `unknown`。
> **不要改写任何已有的记录行** —— 记错了就追加一行，写清 `edited:`。
> 不要给医疗建议，所有数字都是估算。
>
> --- SKILL.md ---
> （粘贴）
> --- profile.md ---
> （粘贴）
> --- 今天 ---
> （粘贴）
>
> 现在：记录这一餐。12:30，食堂，米饭、鱼、青菜。

然后把模型给出的结果**自己复制回** `log/YYYY-MM-DD.md`。

> ⚠️ **第一天你会觉得这一步麻烦。** 但正是这步麻烦，让你明天可以随时换掉这个模型 ——
> 因为文件是你的，不是它的。

### 4. ChatGPT / Gemini / Claude.ai 网页版

同上「方式 B」。粘什么、按什么顺序粘、怎么开头，见英文版
[`../run-with-any-model.md`](../run-with-any-model.md) 第 3 节。

## 四、⭐ 真正的验证：一周之内换一次模型

**这件事只在第一周做一次。它是唯一能证明「数据是你的」不是口号的方法。**

| 步骤 | 做什么 | 你应该看到 |
|---|---|---|
| 1 | 用**模型 A** 记周一到周三 | `log/` 下三个文件，每行都有 `source:` |
| 2 | 换**模型 B**。把 `SKILL.md` + `profile.md` + 三个日志一起粘过去，问：**「总结我这周到目前为止的情况，并给出下一次训练的重量。」** | **和模型 A 给出一样的数字** |
| 3 | 运行 `python3 scripts/parse_log.py log/` | 一张表和两个模型都对得上 |
| 4 | 如果模型 B 的数字不一样 | 分歧在**估算**上，不在**数据**上 —— 这是可以接受的 |

**第 2 步过了，这个项目就是成立的。**
如果一换模型数字就变，说明契约里**缺了一个字段** —— 这正应该开一个 issue，
因为这**就是数据契约存在的意义**。

## 五、换模型时，什么会坏、什么不会

| 会变 | 不会变 |
|---|---|
| 建议的**语气和风格** | 你的 `log/` 历史 |
| 某个 **份量的估算**（不同视觉模型确实有差异） | `profile.md` |
| 工具是否**自动读** `SKILL.md` | 任何你手打并标了 `source: manual` 的数字 |
| 日报的**排版** | **缺口数字**（它是对你自己数据做的算术） |

**规则一句话：契约保护的是「你记录的事实」；模型只能对「你没记录的估算」发表不同意见。**
这个分离，就是全部设计。

## 六、常用命令

```bash
git clone https://github.com/<你>/bodymd && cd bodymd
cp templates/profile.md profile.md      # 改：身高、体重、年龄、蛋白目标
mkdir -p log

python3 scripts/selftest.py             # 验证仓库完好（零依赖）
python3 scripts/validate_log.py log/    # 用契约检查你自己的日志
python3 scripts/parse_log.py log/       # 周聚合
```

**脚本是可选的。** 它们只是读你本来就要手写的那些 Markdown。
**你一行 Python 都不跑，吃练记照样能用。**

## 七、⚠️ 诚实声明

- 仓库里的**适配文件**（`AGENTS.md`、cursor rules、copilot instructions）**结构已就位且正确**。
- 但**端到端集成没有对每个厂商的当前加载器逐一实测** —— 矩阵应该读作「已经接好了」，
  不是「已经验证过」。
- 好消息是：**兜底路径永远存在** —— 那就是粘贴。粘贴不依赖厂商做任何事，所以它不会坏。
