# 出问题了怎么办

这个项目只会坏两件事：**AI 干了契约不允许的事**，或者**文件过不了校验**。
按症状查下面，找到就修。

这里写的每一条都是我实际见过的，不是设想的。你的问题不在表里 → [提 issue](#怎么提问题)，这一页就是这么长出来的。

## 1. AI 不看 SKILL.md

**十个里有九个是这个原因**：工具没打开在仓库目录，或者这一轮对话里根本没喂 `SKILL.md`。

| 你的用法 | 怎么办 |
|---|---|
| 编码类 agent（Claude Code、Codex CLI、Cursor、Copilot） | **打开在仓库目录**，不要打开在上一级。然后说：*读 SKILL.md，开始今天的记录* |
| 网页对话（豆包、Kimi、通义、DeepSeek、ChatGPT、Gemini） | **每次新对话开头都要重新粘贴 `SKILL.md`**。新对话没有上一轮的记忆 |
| 上传到知识库 | 上传一次 `SKILL.md` + `profile.md`，然后说：*严格按 SKILL.md §3.3 输出* |
| 还是飘 | 直接说：*停。重读 SKILL.md §3.3。只输出日志块* —— **报章节号是最强的纠偏** |

如果还不行，说明这个模型消化不了多文件指令。那就**只粘 §3**（数据契约）——真正需要它记住的只有这一段，一条消息装得下。

## 2. 数字不对

| 情况 | 大致误差 | 你该做什么 |
|---|---|---|
| 简单一盘（鸡胸+米饭+西兰花） | ±10-15% | 接受它 |
| 混合菜（咖喱、炒菜、炖菜） | 明显更差 | **说清怎么做的**，不要只说看到了什么。"这盘用 2 勺油炒的" 比换模型有用得多 |
| 餐厅菜 | 最弱的一档 | 分量和隐形脂肪是看不见的。整餐估成一行，然后用 `edited:` 改 |

**最大的单一误差来源是隐形油**：油、黄油、芝麻酱、奶酪、各种酱。如果你长期偏低，先怀疑这个，再怪模型。

改完必须写进 `edited:`：

```markdown
- 12:30 | lunch | 番茄炒蛋 + 米饭 | 540 kcal | P22 C62 F18 | photo: photos/2026-10-12/1230.jpg | source: photo | edited: 米饭按 2 碗计，AI 估 1.5 碗
```

这一行不是记账。**它就是让明天的模型（可能是另一家的）从你的修正开始，而不是从零开始的唯一机制。** 见 `SKILL.md` §3.4。

## 3. 它反复问我早就说过的信息

**原因**：对话是无状态的，跨对话什么都不记得。

**解法**：记忆存在**文件**里，不在对话里。

- `profile.md` —— 你的基线：身高、体重、目标、限制。**填一次就够**。
- `log/YYYY-MM-DD.md` —— 每天一个文件。问周复盘时，把最近 7 天一起给它。

网页对话的用法就是把 `profile.md` + 当天日志 和 `SKILL.md` 一起粘过去。确实要粘三样东西 ——
但这仍然是你唯一能在换工具之后还活着的工作流。

## 4. 它开始给建议（我没要的建议）

契约明令禁止。`SKILL.md` §7 是护栏清单，§9 是「用户想要 App」时的标准回答。

把这段贴给它就行：

> 重读 SKILL.md §7。你是记录系统，不是教练。输出日志块和日报，不要医疗建议、不要评价我吃的东西、不要效果承诺。

如果某个模型坚持要加评论，那是**模型的问题不是契约的问题** —— 换模型。数据不在乎你用谁。

## 5. 报告太长

说 **"一屏"**。它会砍。日报格式在 `SKILL.md` §6，不是写作文的地方。

还长就只要两个数：**缺口** 和 **蛋白缺口**。

---

## 6. 它想从视频里读重量

做不到。`SKILL.md` §5.1 写得很明确：动作类型和次数可以从视频识别，**重量不行** —— 摄像头读不出杠铃片上印的数字。

直接说重量，或者手动敲。两秒钟的事。

没有手环的话，消耗就只能是估算，这是被接受的 —— 不要允许工具假装有它没有的精度。

## 7. 我写过的记录被改了

日志是 **append-only（只追加）**（`SKILL.md` §3.4）—— 它的意思是**不许有静默的改动**，不是「每次改动都要新开一行」。修正的做法是**改那一行自己的 `edited:` 字段**，让这一行自己记录「改了什么、为什么改」：

```markdown
- 13:05 | lunch | 鸡胸 150g + 米饭 + 西兰花 | 570 kcal | P54 C55 F15 | photo: photos/2026-10-12/1305.jpg | source: photo | edited: 米饭 150g->120g
```

**不要把同一顿饭再追加一遍。** 那会让 `## Totals` 重复计算 —— **一顿被算两次的饭，比一顿算错的饭更糟。**

补救：

1. 如果目录在 git 里：`git diff` 看改了什么，`git checkout` 撤销。
2. 没有 git：上一版的数字通常还在你的对话记录里 —— 抄回来，补上 `edited:` 行。
3. 然后告诉 AI：*日志里不许有静默改动 —— 只要改了数字，`edited:` 就必须说明改了什么。*

这也是**建议用 git 私下备份这个目录**的理由。8 个测试档案里有 2 个就是专门用来测这类脏数据的。

## 8. 校验器报 FATAL 或 WARN

**警告不是失败。** 校验器的设计原则是：能降级为警告的绝不当致命错误 —— 记录不完整是常态，一个拒绝你真实一天的校验器是装饰品。只有 `FATAL` 会拦住你。

```bash
python3 scripts/validate_log.py log/
```

退出码：`0` 全过 · `1` 有致命项 · `2` 只有警告。

| 码 | 级别 | 含义 | 怎么改 |
|---|---|---|---|
| V1 | FATAL | 餐食行字段数 < 6 | 对照 `SKILL.md` §3.3 检查行结构 |
| V2 | FATAL | 餐食行缺 `source:` | 每条营养记录都必须标注来源 |
| V3 | FATAL | `source:` 取值非法 | 餐食行只接受 `photo`、`voice`、`manual`、`wearable`、`video+voice`、`estimated`。**训练行、`## Body`、`## Sleep` 用的是各自不同的取值集合** —— 完整表格见 `SKILL.md` §3.4 |
| V4 | WARN | 缺 `edited:` | 没改过就写 `edited: none` |
| V5 | FATAL | 既没有热量数字，也没有显式 `unknown` | 给数字，或给字面量 `unknown` |
| V6 | FATAL | 训练行缺 `exercise:` 或 `reps:` | 两个都是必填 |
| V7 | WARN | 训练行缺 `load_kg:` | 确认不了填 `unknown`；徒手动作填 `bodyweight` |
| V8 | WARN | 时间不是 `HH:MM` | 24 小时制，补零 |
| V9 | INFO | 没找到 `## Meals` 或 `## Training` 段 | 休息日正常；缺 Meals 通常是标题被改了 |
| — | FATAL | 文件不是 UTF-8 | 另存为 UTF-8 |

健康仓库的预期输出：

```bash
python3 scripts/selftest.py                          # 21 项 → 21/21 PASS
python3 scripts/validate_log.py examples/fixtures/   # → 致命 0，警告 2（两条都是故意的）
python3 scripts/parse_log.py    examples/fixtures/   # → 75 天 / 9 个档案
```

**那 2 条警告是故意的** —— 用来证明"缺一个可选字段会降级为警告，而不是拒绝整个文件"。

## 9. 我的 agent 不读 SKILL.md 和 AGENTS.md

先确认文件在你工具期望的路径上：

| 工具 | 它读哪个文件 | 本仓库是否有 |
|---|---|---|
| Codex CLI 及遵循 `AGENTS.md` 约定的工具 | `AGENTS.md` | 有 |
| Cursor | `.cursor/rules/bodymd.mdc` | 有 |
| GitHub Copilot | `.github/copilot-instructions.md` | 有 |
| Claude Code 等 | `SKILL.md`，按需加载 | 有 |

两个真实的限制，直说：

- **这些适配文件是"接好了"，不是"对每一家当前版本都压测过"。** 如果你的工具改了加载逻辑，永远不会坏的那条路是：**把 `SKILL.md` 粘进对话**。
- 有些 agent 只读仓库根目录的 `AGENTS.md`，不会往上找。**打开包含 `AGENTS.md` 的那一层目录。**

## 10. 什么东西绝对不能进公开仓库

你的健康数据就是你自己设备上的一个文件夹。本项目没有服务器、没有统计、没有遥测 —— 所以唯一可能泄露的方式，是你自己把它公开。

`.gitignore` 已经排除 `profile.md`、`log/`、`reports/`、`photos/`。保持这样。

- **绝不**把 `log/` 或 `profile.md` 提交到公开仓库。
- **云同步要留神**：同步过去，那个云就等于替你保管健康数据。可以接受 —— 但要是你**主动决定**的。
- **求助时只给数字，不给身份**。日报格式里没有姓名、地址、账号。任何个人信息替换成 `REDACTED`。

## 怎么提问题

[提一个 issue](https://github.com/adwilds/bodymd/issues/new/choose)。两个模板：一个报 bug，一个提问题。

**请附上：**

1. 用的什么工具 + 什么模型（例如"豆包"、"Claude Code / Sonnet 4.5"）。**模型行为差异很大，这是我一定会问的第一个问题。**
2. 你做了什么、它回了什么 —— **原样贴出来，不要概括**。
3. 那一天的 `log/` 文件，去掉个人信息。**数字是安全的，身份不是。**
4. 如果脚本报错：完整的命令 + 完整的输出。

**改得快的**：数据契约、校验器、工作流、prompt、测试档案。

**会被关掉的**：「做个 App 吧」「加个手机端」「加同步」「自动从视频识别重量」——
这些正是本项目存在的意义就是**不要有**的问题，原因见 `SKILL.md` §5.1 和 §9。
