# 吃练记 · 薄肌手册

**一套跑在你自己 AI 上的身体管理工作流。数据留在你自己的文件里。**

*吃练记，两分钟。数据是你自己的。*

`MIT`（代码）· `CC BY-NC-SA 4.0`（文档）· 只用 Python 3 标准库 · 零依赖

> English → **[bodymd](README.md)**　｜　`吃练记` = 吃 + 练 + 记，每天往你自己的文件里写两分钟

---

## 先说一件让我不爽的事

热量 App 要干两件事：**替你存饭，替你算账。**

第一件它就干得不老实。你的记录在它的数据库里。它涨价、把拍照识别挪进付费墙、被收购 —— 一样都轮不到你同意。而你敲进去的那 200 顿饭，你也带不走。

第二件更糟。**替你想的那部分，绑在它的模型上。** 它一换模型，你的工作流就得跟着改，也没人问过你。

所以我把这两件事拆开了。

## 它到底是什么

不是 App，不是在线服务。没有账号、没有服务器、没有数据库。

**它就是一个文件格式，加一份说明书**，两样都是纯 Markdown：

- 你的记录，是你能选目录的 `.md` 文件。哪年用哪个编辑器都能打开。
- 说明书也是 Markdown，所以**任何一个像样的模型都能读**。
- 你自己带钥匙，或者直接贴进你已经在付钱的那个对话框。
- 这个仓库不存你的数据、不跑推理、不计你的 token。

**周二换个模型，数据一个字都不用动。**

## 一天是怎么过的

晚上 21:40，刚吃完饭。拍两张照 —— 吃之前一张，吃之后一张 —— 连着工作流文件一起丢给你的 AI。

还回来的不是判决书，是**一行你可以跟它吵的账**：

```markdown
## Meals
- 21:12 辣椒炒肉 + 米饭 (2 碗) | 720 kcal · 蛋白 32 g | 顺序: 先蛋白 ✗ | source: photo · conf: medium
- 21:30 一杯酸奶 | 130 kcal · 蛋白 6 g | source: photo
- edited: 米饭 按 2 碗计（AI 估 1.5 碗）；用户改
```

你把米饭的量改对，然后**把「我改过」也写下来**。这条修改就永久留在文件里了 —— 明天换一个模型、换一家公司，它读的还是这个文件，从**你改过的地方**接着算，而不是从零开始。

**最后那一行就是整个产品。** `edited:` 让一套工作流在模型不停换的情况下，越用越准。

然后它把这一天合起来 —— 睡眠、摄入、消耗 —— 告诉你今天在不在缺口里，并且只给你**明天改一件事**。到了周日，它只算一件真正重要的事：**你这七天的体重趋势，跟上七天比** —— 目标从趋势里重算，而不是从你当初随手填的那个数字。

## 整件事的地基

**[`SKILL.md`](SKILL.md) 的第 3 节，是这个仓库存在的理由。那是一个数据契约。**

它规定 `profile.md` 和 `log/YYYY-MM-DD.md` 里每个字段：哪些必须有、哪些可以没有、`unknown` 是什么意思（**它是合法值，猜不是**），以及一条修改该怎么记，才能保证**永远不被悄悄覆盖**。

这个契约一旦稳定，**模型就变成了一个可替换的零件**。这也是这套东西唯一能活过下一次模型发布的原因。

## 怎么开始

### 如果你用编码助手 —— Claude Code / Codex CLI / Cursor / Copilot / Gemini CLI

```bash
git clone https://github.com/adwilds/bodymd && cd bodymd
cp templates/profile.md profile.md     # 基线数字填一次
```

然后对助手说：

> 读 SKILL.md。开始今天的记录。

`AGENTS.md` 负责那些会自动读它的工具；`.cursor/rules/` 和 `.github/copilot-instructions.md` 分别管 Cursor 和 Copilot。**装完了。**

### 如果你用豆包 / Kimi / ChatGPT —— 或者就用一个普通对话框

**不用装任何东西。** 把 `SKILL.md` 和你的 `profile.md` 贴进去（或上传），让它给你今天的记录，结束时把更新后的文件贴回来。

**这样做完全没问题，是正统用法**，不是退而求其次 —— 同一份契约，同一套数据。各工具的具体做法见 [`docs/zh-CN/run-with-any-model.md`](docs/zh-CN/run-with-any-model.md)。

### 如果你只想先看看这套东西到底靠不靠谱

```bash
python3 scripts/selftest.py                          # 13 项检查 → 预期 13/13 通过
python3 scripts/validate_log.py examples/fixtures/   # → 预期 0 致命，2 警告
python3 scripts/parse_log.py    examples/fixtures/   # → 预期 56 天 / 8 个档案
```

第三条命令读的是 8 个测试用户 —— 中国人、华裔美国人、英国人、墨西哥人、尼日利亚人、南亚裔 —— 每人一周。**全部是虚构的，而且是故意做得乱七八糟的**：漏记的午餐、没电的体重秤、蛋白只有 48 g 的一天、完全没记训练的一天。披露与红线见 [`examples/fixtures/README.md`](examples/fixtures/README.md)。

那 **2 条警告是故意的**。它们用来证明：校验器遇到缺一个非必填字段时，会降级成警告，而不是把文件打回去。**记录不完整才是常态，一个会因此拒收文件的校验器，只是摆设。**

## 我没测过什么

一个只列优点的 README 就是广告。所以：

- **各工具的适配文件结构是对的，但我没有真机跑过每一家的当前版本。** 文件都在、都能解析，但没有逐个验证过对接各家加载器的完整链路。**兼容矩阵要读成「已经接好了」，不是「已经验证过」** —— 诚实声明写在 [`docs/zh-CN/run-with-any-model.md`](docs/zh-CN/run-with-any-model.md) 第七节。
- **契约还是第 0 版。** 字段名可能还会改，改的时候我会在 commit 里写明。
- **那 8 个档案是「像不像」用的，不是基准值。** 别把里面的数字抄进你的 `profile.md` 当成建议。
- **目前没有人为它付过钱 —— 这也不是现阶段的目标。**

## 这不是什么

- **不是医疗器械。** 这里没有任何诊断、治疗、治愈。
- **不做任何效果承诺。** 不承诺体重、不承诺周期、不承诺围度。
- **不替代医生、营养师、教练。**
- 这里产生的所有热量、宏量、消耗数字**都是估算** —— 而且文件里就是这么标的。

## 它是怎么来的

**先有工作流，后有代码，这是故意的** —— 你在仓库里能直接看出来：契约、流程、prompt **就是**产品本身。那两个 Python 脚本是用来**检查**它们的，不是用来跑它们的。

它一开始只是一套手写下来的流程：拍餐、拿数字、按顺序吃、记一组训练、晚上看一屏、周日复查 —— 被改写成**不需要任何 App、不需要订阅、不需要绑定哪家公司**的样子。

这个项目还有另一张首页，英文的 [`README.md`](README.md)，名字叫 `bodymd`。**那不是翻译关系** —— 中文这边有不一样的任务：做分发、验证需求是不是真的。选在这里，是因为**只有中国市场，「每隔几周换个模型」不是偏好，是每天的日常**。

**两边的数据格式完全一样。** 一份契约，不维护两套。
